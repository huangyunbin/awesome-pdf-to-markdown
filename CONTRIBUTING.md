# Contributing to awesome-pdf-to-markdown

Thanks for taking the time to contribute! This list exists to help researchers, students, and AI engineers find the right tool for their needs — your contributions make it more useful for everyone.

## How to Add a Tool

1. **Check it's not already listed.** Search the README before submitting.
2. **Fork the repository** and create a branch: `git checkout -b add-toolname`
3. **Add your entry** in the appropriate section of `README.md`
4. **Submit a pull request** with a clear description of what you're adding and why it belongs here.

## Inclusion Criteria

A tool will be included if it meets **all** of the following:

- ✅ It converts PDF files to Markdown output (or is a critical part of such a pipeline)
- ✅ It is actively maintained (last commit within 12 months, or a stable web service)
- ✅ It has meaningful differentiation from already-listed tools
- ✅ It is publicly available (open source or has a public web interface/pricing)

## What Makes a Good Entry

Each tool entry should include:

```markdown
### Tool Name

**[link](https://example.com)** — Short one-line description.

**Key Features:**
- Feature 1
- Feature 2

**Best for:** Who this tool is ideal for.

**Limitations:** Honest weaknesses — we value accuracy over promotion.
```

## Quality Standards

- **Be honest about limitations.** A tool that's great at one thing but weak at another should say so.
- **No paid promotions.** Do not submit tools in exchange for compensation. We can usually tell.
- **English only** — The README is in English to serve the global GitHub audience.
- **Use real data.** If you mention accuracy claims, link to a benchmark or test result.

## Updating Existing Entries

If a tool has changed (new features, pricing changes, project abandoned), open a PR or Issue with the updated information. Include a source link.

## Reporting Issues

Use GitHub Issues to:
- Report a tool that has been abandoned or shut down
- Suggest a new tool for consideration
- Correct inaccurate information

## Code of Conduct

Be respectful. Criticism of tools should be technical and constructive, not personal.
